Agents

What an AI agent is

A model answers. An agent receives a goal, chooses which operations to call, checks the result and stops when it is done or when it cannot go on.

01

Model, assistant, agent

They are three different things, and they are confused all the time. The difference is not how intelligent the model is: it is how much autonomy it has, and who set its boundaries.

ModelGenerates an answer and stops
AssistantAnswers, one question at a time
AgentReceives a goal, acts, checks

02

One question, one record

It looks like an ordinary conversation. Underneath, every field is the result of a declared operation on the company database: no free-form search, no data recalled from memory.

Find me the customer record for Rossi
1 tool call 4 s
Here is the record of the customer found with “Rossi” (cerca_clienti, id 1):

Customer

Company nameRossi & C. S.r.l.
VAT number01234567890
Emailinfo@rossiec.it
Phone075785869
Contact personMario Rossi
Balance due1.240 €
One result only. If you want the full details (overdue invoices, orders), tell me.

No free-form search: the agent’s only action is the operation it was given, run with the requester’s permissions.

How much did we spend on transport in the first half of the year?
2 tool calls 7 s
DATA MISSING · no “transport” line in the chart of accounts
I will not estimate it. spese_per_categoria returns seven categories and none of them is transport: the spending may sit inside “logistics” or be recorded as general costs.
Look inside logistics
1 tool call 3 s
Logistics, January–June 2026: 18.940 € across 62 documents. If you want, I can check which ones are actual transport and which are warehouse, but that means reading the individual entries.

The moment that sets a serious system apart: declaring what isn’t there instead of producing a plausible number.

03

When the data isn’t there

The question is legitimate, the answer is not in the data. The agent says so, explains where it might be, and waits for an instruction instead of filling the gap.

04

What it is for, and what it is not for

The useful question is not whether an agent can do something, but whether that something is repetitive, verifiable and bounded.

Use it when

The work repeats and follows a recognisable rule
The information sits in archives that can be reached
There is a way to check that the result is right
The task crosses several steps and several tools

Do not use it when

The decision needs a person to take responsibility
The process does not exist yet, or changes every time
There is no way to check the outcome
The problem is solved by one well-written rule

05

How it is built inside

A serious agent is four things put together, and none of the four is the model. The model is the replaceable part.

ToolsDeclared operations, with an MCP server in front
BoundariesPermissions in the database and in the operating system
EvidenceEvery statement traces back to a read
OperationLog, restarts, monitoring

06

Why it is being asked for now

Three things changed in the same period, and together they make possible what would not have held up two years earlier. None of the three is about the intelligence of the model itself.

ModelsThey hold up on tasks with several steps
ToolsOperations are declared instead of improvised
CostContinuous work has become cheap

The definition I use

An agent is not a more intelligent model. It is a model with boundaries.

Stated limit

An agent does not remove the work of the person who decides. It moves it: from carrying things out to setting goals, scope and criteria for checking. If nobody does that part, the system does not hold up.
