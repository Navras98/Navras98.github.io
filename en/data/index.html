Data

The model picks, it does not read

Between the model and the archive there is a set of operations written by hand. The model picks which one to call, and gets back what that operation actually read.

01

Three outcomes, never two

Confusing the last two is the flaw that makes numbers get invented.

OutcomeNameWhat comes back
01 Data present It comes back as it is written in the archive, comparable with what was read.
02 Data absent Declared absent. Not reconstructed, not estimated, not rounded.
03 Read failed A visible error, never a plausible answer in place of a true one.

02

A closed list, not free access

Every operation has a name, parameters and a predictable result. Outside that list there is nothing to call: a question that matches no operation does not get an approximate answer.

AccessOperations written in advance
Off the listA refusal, not an estimate
NumbersTraceable to the value that was read

Why it matters

A number that is not in the database must not turn into a plausible number.

Stated limit

Determinism holds inside the perimeter of the written operations. A question that falls outside does not get a better answer: it gets a refusal, and a new operation has to be added.
