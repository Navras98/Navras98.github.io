Training and consulting

I teach you how, or I build it with you

Four ways of working together, from a single meeting to a system that is built and maintained. Always on your case, never on textbook examples.

What I offer

The difference between the four is not how long they last: it is who keeps a hand on the system at the end.

01

Consulting

One or more sessions to decide: whether an agent is needed, where it is worth putting one, what should be left to a person. I come out with a written scope, not with a generic quote.

02

Training

I teach how to build agents: how operations are declared, how they are connected to the data, how what they say is verified. On real tools, with your own case in hand.

03

Security hardening

I take a system that is already running and I close it down: permissions in the database, execution isolation, tests that the restriction holds even when the model tries to work around it.

04

Custom-built systems

I design and build the system, for one person or for a company: on the goals you have, on the data you have, inside the security boundaries that are needed.

01

How it proceeds

The same order, whether it is a single session or an entire system. The scope before the code, the verification before the delivery.

FirstWe work out the goal and the work that is done by hand today
SecondWe write the scope: what the agent can do, what it must not be able to do
ThirdWe build: declared operations, permissions, checks
FourthWe try to break it, before someone else does
FifthMaintenance: periodic checks and updates when the numbers move

02

Who it is for

Two different starting points, two different paths. The first question I ask is always the same: what is the work you do by hand today.

If you are starting from scratch

What an agent is and what it is not
How it connects to data and programs already in use
How to recognise a verifiable result
What should be automated and what should not

If you already have something running

Where the permissions really are
Why the system answers well in a test and badly in service
How to put a check between whoever executes and whoever approves
How to move from a cloud model to a local one, and when it is worth it

The criterion

I do not teach how to write better instructions. I teach how to build boundaries.

Stated limit

I do not promise results before I have seen the data and the process: the cost and the time depend on the scope, and the scope is written together. If after the first meeting the answer is that an agent is not needed, I say so.
